03 · Verifix

Мониторинг исполнения договоров

Чтобы проверить исполнение договора, сотруднику строительной СРО (саморегулируемой организации) нужно сопоставить сведения из 1С, ЕИС (Единой информационной системы в сфере закупок) и документов. Важно понять, где есть риск, а где для вывода пока не хватает данных.

Verifix собирает эти сведения в одном рабочем пространстве. Реестр помогает выбрать договор для проверки. В карточке можно изучить основание сигнала, этапы, приёмки, оплаты и подтверждающие документы.

Моя роль

Разрабатываю продукт с нуля с помощью AI-инструментов и напрямую работаю с заказчиком. Сотрудничаю с дизайнером и специалистом по 1С. Развиваю систему по мере её использования.

Статус

Заказ на разработку оплачен. Системой пользуются несколько сотрудников заказчика. Следующий этап — измерить время работы с договором и объём ручной проверки.

Как выбрали первый объём

Исходный запрос охватывал несколько процессов: проверку компаний, работу с документами и контроль исполнения договоров. Для первого этапа выбрали мониторинг договоров: этапы, сроки и базовую проверку документов. Интеграции с 1С и Госзакупками включили в первый этап — данные должны поступать из существующих источников.

От списка файлов — к рабочей таблице по договору

Задача. В карточке договора накапливаются акты, платёжные документы, дополнительные соглашения и другие файлы. Сотруднику нужно найти конкретные сведения и сопоставить документы. Длинный список файлов не помогает быстро увидеть нужные данные.

Подход. Предложила организовать документы по типам. Акты, платежи и претензии отвечают на разные вопросы, поэтому для них нужны разные наборы полей. Общие сведения — источник, номер, дата, сумма и статус разбора — связывают документы в единую рабочую таблицу.

Моя роль

Уточнила пользовательский сценарий и пересмотрела структуру представления документов. Предложила группировать их по типам вместо этапов договора: в большинстве рассматриваемых договоров нескольких этапов нет. Уточнила нужные сведения — источник документа и состав работ — и предложила рассматривать претензии отдельно. Поддержала чат на уровне конкретного документа как направление развития.

Статус

Текущая версия развёрнута в production. Фича развивается.

Ожидаемая польза

Меньше ручного поиска по файлам и более удобное сопоставление сведений по договору.

Продуктовые решения

Группировать по содержанию

У актов, платежей и претензий разные задачи. Группировка по типам позволяет показывать нужные для каждого типа сведения и не дублировать раздел этапов договора.

Сначала — полезное представление данных

В плане первый релиз строится на уже извлечённых сведениях. Чат, колонки-вопросы и подробный разбор состава работ выделены в следующие этапы развития.

Разделить обзор и уточнение

Таблица предназначена для сопоставления документов по договору. Работа с конкретным файлом — отдельный уровень, где можно изучить первоисточник и уточнить детали.
